# Budget Meal Finder 프로젝트 문서

## 1. 프로젝트 개요 (Project Overview)

### 1.1. 프로젝트 목적 및 핵심 기능

**Budget Meal Finder**는 사용자가 설정한 예산과 현재 위치를 기반으로 주변 식당의 메뉴를 추천해주는 웹 애플리케이션입니다. 이 프로젝트의 핵심 목표는 사용자가 제한된 예산 내에서 만족스러운 식사를 할 수 있도록 돕는 것입니다.

- **예산 기반 필터링:** 사용자가 입력한 예산에 맞는 메뉴 정보만 필터링하여 제공합니다.
- **위치 기반 검색:** 사용자의 현재 위치를 중심으로 주변 식당 정보를 제공합니다.
- **사용자 참여:** 누구나 식당 및 메뉴 정보를 등록, 수정, 삭제할 수 있어 최신 정보를 유지합니다.
- **인증 시스템:** JWT 기반의 회원가입 및 로그인 기능을 통해 사용자별 설정을 관리할 수 있습니다.

### 1.2. 사용자 시나리오 (User Scenarios)

- **시나리오 1: 맞춤형 추천**
  > "나는 회원가입하고 로그인하여 내 예산 정보를 저장하고 싶다. 그렇게 하면 언제 접속하든 나에게 맞는 메뉴를 추천받을 수 있다."

- **시나리오 2: 예산 설정**
  > "나는 7,000원을 입력하여 그 예산으로 먹을 수 있는 메뉴만 추천받고 싶다."

- **시나리오 3: 위치 기반 검색**
  > "나는 현재 내 위치 주변의 식당 중에서 예산에 맞는 메뉴만 보고 싶다."

- **시나리오 4: 정보 기여**
  > "나는 내가 아는 식당의 메뉴와 가격, 그리고 내 리뷰를 다른 사람들과 공유하고 싶다. 또한, 정보가 변경되면 직접 수정하고 싶다."

## 3. 주요 기능 및 설계 의도 (Key Features & Design Intent)

### 3.1. 사용자 인증 및 계정 관리

- **JWT 기반 인증:** 사용자는 이메일과 비밀번호로 회원가입 및 로그인을 하며, 서버는 JWT(JSON Web Token)를 발급하여 이후의 모든 요청에 대한 사용자를 식별합니다. 이 방식은 서버가 세션을 유지할 필요가 없는 **Stateless** 구조를 가능하게 합니다.
- **비밀번호 암호화:** `bcrypt` 라이브러리를 사용하여 사용자의 비밀번호를 안전하게 해싱하여 데이터베이스에 저장합니다.
- **계정 정보 변경:** 사용자는 설정 페이지에서 자신의 이메일과 비밀번호를 안전하게 변경할 수 있습니다.
- **계정 삭제:** 사용자가 계정을 삭제할 경우, 해당 사용자가 작성한 모든 메뉴 및 식당 정보가 함께 삭제되는 **계단식 삭제(Cascading Deletes)** 로직을 애플리케이션 레벨에서 구현하여 데이터 무결성을 유지합니다.

### 3.2. 메뉴 및 식당 정보 관리

- **CRUD 기능:** 사용자는 지도 상의 위치에 새로운 식당과 메뉴 정보를 등록(Create), 조회(Read), 수정(Update), 삭제(Delete)할 수 있습니다.
- **이미지 업로드:** 메뉴 등록 시 `multer`를 사용하여 이미지를 서버에 업로드할 수 있으며, 클립보드의 이미지를 직접 붙여넣는 편의 기능(Clipboard API 활용)도 제공합니다.
- **페이지 간 상태 전달:** 설정 페이지에서 '수정' 버튼을 누르면, `localStorage`를 통해 수정할 메뉴의 ID를 메인 페이지로 전달하여 즉시 수정 다이얼로그를 띄워주는 방식으로 사용자 경험을 개선했습니다.

### 3.3. 지도 기반 검색 및 시각화

- **위치 기반 검색:** 사용자의 현재 위치 또는 지도의 중심점을 기준으로 주변 식당 정보를 동적으로 불러옵니다.
- **고급 검색 및 정렬:** 사용자는 예산, 카테고리, 키워드 등 다양한 조건으로 메뉴를 필터링하고, 가격, 추천 수, 최신순으로 정렬할 수 있습니다. 이는 서버 측(`GET /api/menus/advanced-search`)에서 효율적으로 처리됩니다.
- **마커 클러스터링:** 지도에 표시할 마커가 많을 경우, `@googlemaps/markerclusterer` 라이브러리를 사용하여 가까운 마커들을 그룹화하여 보여줌으로써 가독성과 성능을 향상시켰습니다.

### 3.4. 사용자 상호작용

- **추천/비추천 기능:** 사용자는 각 메뉴에 대해 추천 또는 비추천 투표를 할 수 있습니다. 사용자의 투표 기록은 `User` 모델에, 총 투표 수는 `Menu` 모델에 각각 저장하여 중복 투표를 방지하고 빠른 조회를 가능하게 하는 **하이브리드 데이터 관리 방식**을 사용합니다.
- **시각적 피드백:** 사용자가 이미 투표한 메뉴는 버튼 색상을 다르게 표시하여 직관적인 피드백을 제공합니다. 이는 서버로부터 사용자의 투표 기록을 받아와 UI 상태에 반영하는 **Stateful UI** 패턴을 통해 구현되었습니다.

### 4.2. 백엔드 아키텍처 (Layered Architecture)

백엔드는 **계층형 아키텍처(Layered Architecture)** 를 채택하여 각 로직을 역할에 따라 분리하고 코드의 재사용성과 유지보수성을 높였습니다.

- **`routes`**: HTTP 요청을 받아 적절한 컨트롤러로 연결하는 라우팅 계층.
- **`controllers`**: 요청을 받아 비즈니스 로직(서비스)을 호출하고, 결과를 클라이언트에 응답하는 계층.
- **`services`**: 애플리케이션의 핵심 비즈니스 로직을 처리하는 계층. 여러 리포지토리를 조합하여 복잡한 작업을 수행.
- **`repositories`**: 데이터베이스와의 상호작용(CRUD)을 담당하는 계층. 데이터베이스 종속적인 코드를 한 곳으로 모아 관리.
- **`models`**: Mongoose를 사용하여 데이터베이스 스키마를 정의하는 계층.
- **`middleware`**: 요청 처리 과정에 개입하여 인증(JWT), 에러 처리, 유효성 검사 등을 수행하는 계층.

### 4.3. 데이터베이스 스키마

- **`User`**: 사용자 정보를 저장. `username`, `email`, `password`(해시됨) 필드를 가지며, 사용자가 추천/비추천한 메뉴 ID 목록을 포함.
- **`Restaurant`**: 식당 정보를 저장. `name`, `address`, `location`(GeoJSON), `category` 필드를 포함. 위치 기반 검색을 위해 `2dsphere` 인덱스가 설정됨.
- **`Menu`**: 메뉴 정보를 저장. `restaurantId`를 통해 식당과 연결되며, `name`, `price`, `description`, `recommendations`(추천 수) 등의 필드를 포함.
